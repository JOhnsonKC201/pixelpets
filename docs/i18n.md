# Languages

pixelpets speaks more than English in the parts listed below. This page says
what is translated, how the app picks a language, and how to fix a word or add
a language. No code is needed for either.

## What is translated

| Surface | Status |
| --- | --- |
| Quick Tools launcher (list, hints, footer) | Translated |
| What the pet says about timers, to-dos, notes, clips, battery, eye rest | Translated |
| Settings window | English only |
| Tray menu, including coat names, breeds and music moods | Translated |
| Reminders, email, calendar, break and Focus Guard messages | English only |
| First-run tips, update messages, Report a problem | English only |

A surface moves over whole, never half: a menu that is Spanish on three rows
and English on the rest is worse than one that is English throughout.

Shipped languages: English (`en`), Spanish (`es`), French (`fr`), German (`de`),
Brazilian Portuguese (`pt-BR`), Hindi (`hi`), Japanese (`ja`) and Simplified
Chinese (`zh-CN`).

**The seven non-English files have not been reviewed by native speakers.** They
were written carefully, but expect an odd word here and there. Corrections are
very welcome and are a good first contribution.

## How the app picks a language

1. Settings > Tools > Language, when it names a language.
2. Otherwise ("Auto") the first of your system's preferred languages that has a
   file here, in the order you ranked them in your OS settings.
3. A regional variant with no file of its own reads the closest one (`pt-PT`
   reads `pt-BR`, `es-MX` reads `es`).
4. Traditional Chinese (`zh-TW`, `zh-HK`, `zh-Hant`) does not read the
   Simplified file: it is a different script, so it moves on to your next
   language.
5. English, when nothing matches.

A sentence missing from a language falls back to English on its own, so a
half-finished file never shows a raw key.

## What never changes

- **The words you type.** `todo`, `note`, `done 2`, `timer 10m`, `clip` and the
  search prefixes `g`, `ddg`, `b` are commands, the same in every language.
- **English names still match.** Typing `settings` finds the Settings row under
  any language, next to its translated name.
- **What a result does.** The language changes wording only. A test runs every
  route in every language and compares the actions.

## Fix a word

Each language is one flat JSON file in [`src/locales/`](../src/locales). Find
the sentence, change it, run `npm test`, open a pull request.

```json
"say.timer.cancelled": "Temporizador cancelado.",
"timer.item.title": "{label}: quedan {time}",
```

- Keep every `{placeholder}` exactly as English has it. You may move it
  anywhere in the sentence.
- Do not translate the typed commands inside examples (`todo`, `open notes`).
- Keep `Settings > Tools` in English for now: that window is not translated,
  so it is what the user will actually see.
- `tray.workMode` has a `{toy}` slot that is filled with `pet.cat.playNoun`
  (butterfly) or `pet.dog.playNoun` (ball). Word it so both read correctly.
- Coat names (`coat.*`) should be the names cat owners use in your language,
  not word-for-word translations.
- Plain text only. No markup, and no en or em dashes.
- Launcher hints (`hint.*`) sit in a narrow column. Keep them to a word or two.

A sentence that changes with a number is an object, keyed by the plural forms
your language has (`one`, `few`, `many`, `other`, ...). `other` is required:

```json
"nudge.todo": {
  "one": "One to-do still open today. Want to knock it out?",
  "other": "{count} to-dos still open today. Pick one?"
}
```

## Add a language

1. Copy `src/locales/en.json` to `src/locales/<code>.json` (a BCP 47 tag such
   as `it`, `ko` or `pt-PT`) and translate the values.
2. In [`src/i18n.js`](../src/i18n.js), add it to `LANGUAGES`, with the name the
   language calls itself, and to `TABLES`.
3. Add the matching `<option>` to the Language list in `src/settings.html`.
4. Run `npm test`. `tests/i18n.test.js` checks that the file has exactly the
   English keys, the same placeholders, only plural forms the language really
   has, and that Settings lists exactly the languages that ship.

Right-to-left languages (Arabic, Hebrew, Persian, Urdu) need the launcher
layout mirrored first. That is not done yet, so please open an issue before
starting one.

## For contributors: how it works

- `src/i18n.js` is pure (no Electron). `translator(code)` returns
  `t(key, vars)`; `resolveLocale(setting, systemLanguages)` picks the code.
- `src/main/lang.js` binds that to the running app: one `lang.t` made in
  `main.js` and handed to the tray menu, Quick Tools and the updater.
- Only the main process translates. Windows are sandboxed and cannot read the
  locale files, so main sends each window finished strings: launcher rows from
  `src/tools/commands.js`, the launcher's own labels in the `launcher:reset`
  payload.
- A window must never decide anything by reading text. The launcher keys on
  ids and flags (`section`, `checkbox`), and a test pins that.
- `t()` fills only the placeholders it is given. `{name}`, `{time}` and
  `{date}` pass through untouched for `notify()` to fill later.
- `src/tools/system.js` returns `{ ok: false, key, vars, message }`. `key` is
  what gets translated; `message` is the English text for logs and tests.
- Every key must be used and every used key must exist; the same test file
  checks both, so a renamed key cannot leave a dead sentence behind.
